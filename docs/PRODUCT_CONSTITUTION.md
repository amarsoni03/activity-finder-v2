# PROJECT CONSTITUTION (Highest Priority)

This document defines the permanent product philosophy. It overrides all previous prompts, design decisions, and common marketplace patterns.

## CORE IDEA

This platform helps people find activities that fit their free time and location.

We are NOT selling studios.  
We are NOT selling teachers.  
We are selling activities.

The activity is always the primary entity.  
Studios, instructors, and providers are supporting information.

## MISSION

When a user visits the platform, they should immediately be able to answer:

• What activities are available?  
• Do they fit my schedule?  
• Are they near me?  
• When do they start?  

Everything else is secondary.

## NON-NEGOTIABLE RULES

1. Every feature must reinforce:  
   **Course First. Studio Second.**

2. The homepage must immediately present the search experience.

3. Primary search flow must remain:  
   Category (optional)  
   → Metro  
   → Available Time  
   → Search

4. Users browse activities—not studios.

5. Search results represent activities only.

6. Every activity card must prioritize:
   - Activity Title
   - Category
   - Schedule
   - Start Date
   - Frequency
   - Metro Station
   - Travel Time
   - Level
   - Price
   - Rating
   - Short Description
   - Reserve Spot CTA

7. Studio and Instructor information must never dominate:
   - Homepage
   - Search
   - Search Results
   - Navigation
   - Activity Cards

8. Studio, Instructor, Reviews, Contact, Policies, and Provider details belong primarily on the Activity Details page.

9. The interface must answer:  
   **What can I do?**  
   **When can I do it?**  
   **Where can I do it?**  
   within a few seconds.

10. Every new feature must improve activity discovery.  
    If it does not directly help users discover activities that fit their free time and location, it must be secondary, hidden, or removed.

11. AI, recommendations, personalization, and future features must support the search experience—not replace it.

12. Avoid copying studio-first marketplaces.  
    Do not redesign the product around providers.

13. Maintain a calm, minimalist interface:
    - generous whitespace
    - clean typography
    - structured cards
    - low cognitive load
    - minimal visual noise

14. Use accent colors only for:
    - active filters
    - badges
    - buttons
    - icons
    - status indicators

15. Preserve existing functionality while improving the product around this philosophy.

## IMPLEMENTATION RULE

Before implementing any component, page, or feature, first verify that it aligns with this Product Constitution.

If a proposed implementation conflicts with this philosophy, choose the implementation that best supports the Product Constitution, even if it differs from common marketplace conventions.

## FINAL GOAL

Every user should leave with the feeling:  
*"I had free time, and this platform quickly helped me find the right activity nearby."*

This philosophy must guide every future design and development decision.
